# site

The website at agent-custody.dev, generated by VitePress from the repository's own markdown: the root README (by region), the receipts guides, the state and Python READMEs. Nothing here is a second copy of the docs. The site's own pages are the landing page, the guide index pages, and the receipt specification at `/receipt/v0.2`, which is the URL every receipt's `predicateType` carries.

```bash
bun run site:dev      # from the repository root; live reload
bun run site:build    # site/.vitepress/dist
```

Relative links in the docs are rewritten at build time: links to markdown pages become site links, links to source files become links into the repository on GitHub.

## Rules for site changes

- `bun run site:build` must pass. It fails on dead links.
- Root README sections that the site includes are fenced by `<!-- #region name -->` markers. Keep the markers.
- `site/reference/` is written by hand, because TypeDoc does not support the workspace's TypeScript 7.
- `site/security.md` is the vendor questionnaire. Keep it true, keep every "no" a no, and date it.
- `site/faq.md` says where the data goes. Keep it true when recording or exporting changes.
- `site/early-access.md` must stay honest: no independent witness runs yet (issue #6).
- No test runs the Cedar rules on the landing page or in `site/use-cases.md`. Check each one against the Cedar evaluator by hand. In `use-cases.md`, write "no runnable example yet" rather than imply an example.
- The landing page decodes its receipt card from the `gateway-denied` conformance vector at build time. Its measured numbers come from `packages/receipts/scripts/bench.ts`.
- The landing page (`site/index.md`, rendered by `Landing.vue`) is clean and quiet. It uses Inter, which VitePress bundles, so the page makes no font request to Google. It uses a stone neutral palette and one amber primary action. The tokens are in the header comment and the `<style>` blocks of `Landing.vue`. `custom.css` maps the docs pages to the same palette. The primary action is "Run the refund demo locally" (issue #117). It leads to the demo command: `git clone https://github.com/svayatta/agent-custody && cd agent-custody && bun install && bun run demo`. The top bar has these entries: Overview, The demo, How it works, Policies, Use cases, Pricing, Docs, theme, GitHub, Sign in. The sections, in order: hero (with the receipt card), integrations, product overview (the film, with chapters), the problem, the refund demo, how it works, policies, receipts compared with logs and traces (with the measured numbers), use cases, run the demo, footer. Headings are plain and descriptive. The page has no eyebrow labels, no slogans, and no badges in the hero.
- The refund demo section (`Demo.vue`) shows only steps that `bun run demo` (`packages/receipts/scripts/demo.ts`) performs. Its terminal lines come from one real run of the demo. Steps 1 to 4 each join a call (section 1 of the demo) with the auditor output for its receipt (section 2). Step 5 counts the checks of section 2. Every left-out run of PASS lines is marked with its count. Change `Demo.vue` in the same commit when the demo's calls, policy, or verifier check names change. Add a step only when the demo performs it. Approvals (#111), provider timeouts (#112), and reviewer export (#113) join the story when they ship.
- The film chapters in `Landing.vue` use the cue times of `promo.vtt`. Update them when the film is re-cut.
- `Flow.vue` appears on the landing page and in `guide/getting-started.md`. It uses the VitePress variables, so it works in both places.
- The portal and admin pages stamp `data-theme` on `<html>` before paint, from `agent-custody-theme` in localStorage. Their dark tokens sit under both `:root:not([data-theme="light"])` in the media query and `:root[data-theme="dark"]`. Keep both selectors.
- The logo is a receipt with a torn edge, two ledger lines, and a tick on the amber tile. The logo paths are in `site/public/logo.svg`, `favicon.svg` (a copy), the PNG icons (rendered with `rsvg-convert`), `wordmark.svg`, `Landing.vue`, the portal's header and `FAVICON`, and the Caddy `(favicon)` snippet. Change all of them together.
- The promo video (`site/public/promo.mp4`, poster `promo-poster.jpg`) is narrated by the ElevenLabs voice Sarah. Its scenes, in order: the problem, the solution, the architecture (the same diagram as `Flow.vue`), and the refund story of `packages/receipts/scripts/demo.ts`, with illustrative characters as the proof. The agent actions in the problem scene are illustrative. Every receipt field, policy limit, and check name in the video comes from a real run of `bun run demo`. `promo.vtt` must match the narration word for word. Re-cut the video, with the same voice, when the demo's calls, policy, or verifier check names change. The film sits in its own "Product overview" section under the hero, with chapters.
- Each blog piece in `site/blog/` ties to something runnable. Date it by hand. The blog has no feed.
- `site/custody.md` shows the custody hook of this repository. `site/public/custody/` holds sample receipts, the public key, and the policy.
