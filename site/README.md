# site

The website at agent-custody.dev, generated by VitePress from the repository's own markdown: the root README (by region), the receipts guides, the state and Python READMEs. Nothing here is a second copy of the docs. The site's own pages are the landing page, the guide index pages, and the receipt specification at `/receipt/v0.2`, which is the URL every receipt's `predicateType` carries.

```bash
bun run site:dev      # from the repository root; live reload
bun run site:build    # site/.vitepress/dist
```

Relative links in the docs are rewritten at build time: links to markdown pages become site links, links to source files become links into the repository on GitHub.

The live Codex recovery guide lives in [`packages/receipts/docs/codex-recovery.md`](../packages/receipts/docs/codex-recovery.md) and is published at `/receipts/codex-recovery`; the example directory links to that guide.

The gateway reference and receipt specification cover financial operation outcomes and reconciliation; the complete configuration and recovery guide lives in `packages/receipts/docs/financial-operations.md`.

## Rules for site changes

- `bun run site:build` must pass. It fails on dead links.
- Root README sections that the site includes are fenced by `<!-- #region name -->` markers. Keep the markers.
- `site/reference/` is written by hand, because TypeDoc does not support the workspace's TypeScript 7.
- `site/security.md` is the vendor questionnaire. Keep it true, keep every "no" a no, and date it.
- `site/faq.md` says where the data goes. Keep it true when recording or exporting changes.
- `site/early-access.md` must stay honest: no independent witness runs yet (issue #6).
- No test runs the Cedar rules on `site/advanced.md` or in `site/use-cases.md`. Check each one against the Cedar evaluator by hand. In `use-cases.md`, write "no runnable example yet" rather than imply an example.
- The measured numbers on `site/advanced.md` come from `packages/receipts/scripts/bench.ts`.
- The landing page (`site/index.md`, rendered by `Landing.vue`) speaks to one reader: an engineer who runs a coding agent, such as Claude Code, against a system that touches production. It is clean and quiet. It uses Inter, which VitePress bundles, so the page makes no font request to Google. It uses a stone neutral palette and one amber primary action. The tokens are in the `<style>` blocks of `Landing.vue`. `custom.css` maps the docs pages to the same palette. The hero is the shared message (below): the headline "Proof of what your AI agents did." and the line "Give your agents real power, without losing control of them.", then the coding agent as the place to start: the two commands `npm install -g @agent-custody/receipts` and `agent-custody init claude-code` (the npx form appears as a quick try, with a caveat), and a card of one denied call. The sections, in order: the hero, what you see (the report), the incident replay, what the hook does not stop, the closing command, and the footer. The top bar has these entries: What you see, Incident replay, Limits, Advanced, Pricing, Docs, theme, GitHub, Sign in. The hero and the first screen do not use "custody" (except in the name of the product), "chain of custody", "Merkle", "Cedar", or "principal". The word "receipt" comes only after the page shows what a receipt does. The copy never says "first", "only", or "the industry's". The page says "each shell command, file edit, and MCP tool call", never "each tool call", because the hook matcher misses Read, Grep, Glob, WebFetch, WebSearch, and Task. The page claims nothing that is not live: no independent witness runs yet, and the hosted log has no mainnet anchor yet.
- One message in every place. The headline is "Proof of what your AI agents did." The second line is "Give your agents real power, without losing control of them." The README, the landing page, the meta and `og:description` tags, the npm and PyPI descriptions, and the GitHub description all start with these two lines. Short places use only the two lines. Longer places add how it works, in words true for that place: on the landing page, "each shell command, file edit, and MCP tool call", never "every action". Coding agents and payments are examples under the message, never the headline.
- The terminal text on the landing page is real output. The report is the output of tutorial 36 (`packages/receipts/examples/36-claude-code-init.ts`), and the replay lines are from tutorial 38 (`38-incident-replay.ts`), which re-checks three receipts offline and one denied receipt with a key that is not the agent's. The page `guide/incident-replay.md` pastes the full output of tutorial 38. Paste the output again when the example, the starter policy, or a check changes. The receipt ids differ on each run, so the pages show the ids of one run.
- `advanced.md` holds what moved off the landing page: the film, the problem, the refund demo (`Demo.vue`), how it works (`Flow.vue`), the policies, the comparison with logs and traces, the use cases, and a table that links every other part. Every page that the old landing page linked is linked from `advanced.md`. The refund demo (`Demo.vue`) shows only steps that `bun run demo` (`packages/receipts/scripts/demo.ts`) performs. Its terminal lines come from one real run of the demo. Steps 1 to 4 each join a call (section 1 of the demo) with the auditor output for its receipt (section 2). Step 5 counts the checks of section 2: it lists only each receipt's id, its check count, and its result. Each of steps 1 to 4 ends its PASS lines with one total of the checks that it leaves out. Change `Demo.vue` in the same commit when the demo's calls, its policy, or the verifier's checks (names or number) change. Add a step only when the demo performs it. The film chapters in `advanced.md` use the cue times of `promo.vtt`. Update them when the film is re-cut.
- `Flow.vue` appears on `advanced.md` and in `guide/getting-started.md`. It uses the VitePress variables, so it works in both places.
- The portal and admin pages stamp `data-theme` on `<html>` before paint, from `agent-custody-theme` in localStorage. Their dark tokens sit under both `:root:not([data-theme="light"])` in the media query and `:root[data-theme="dark"]`. Keep both selectors.
- The logo is a receipt with a torn edge, two ledger lines, and a tick on the amber tile. The logo paths are in `site/public/logo.svg`, `favicon.svg` (a copy), the PNG icons (rendered with `rsvg-convert`), `wordmark.svg`, `Landing.vue`, the portal's header and `FAVICON`, and the Caddy `(favicon)` snippet. Change all of them together.
- The promo video (`site/public/promo.mp4`, poster `promo-poster.jpg`) is narrated by the ElevenLabs voice Sarah. Its scenes, in order: the problem, the solution, the architecture (the same diagram as `Flow.vue`), and the refund story of `packages/receipts/scripts/demo.ts`, with illustrative characters as the proof. The agent actions in the problem scene are illustrative. Every receipt field, policy limit, and check name in the video comes from a real run of `bun run demo`. `promo.vtt` must match the narration word for word. Re-cut the video, with the same voice, when the demo's calls, policy, or verifier check names change. The film sits in its own "Product overview" section under the hero, with chapters.
- Each blog piece in `site/blog/` ties to something runnable. Date it by hand. The blog has no feed.
- `site/custody.md` shows the custody hook of this repository. `site/public/custody/` holds sample receipts, the public key, and the policy.
